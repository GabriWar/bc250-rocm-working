BC-250: L2 page-table cache configuration knobs (GFXHUB + MMHUB).

FORCE_MISS makes the L2 page-table line cache miss every time, forcing the
walker to re-read PDE/PTE from memory. It needs no invalidation, which is
what makes it usable on a board where invalidation does not complete.

Measured: force_miss=7 on both hubs -> 6 of 10 runs still dirty. The cache
is not the source. See docs/22.

/* BC-250/gfx1013: page TABLE cache configuration inside the L2.
 *
 * Why these knobs exist
 * ---------------------
 * This board's defect is the GPU delivering, for one VA, the content of ANOTHER
 * live allocation -- in whole blocks, with 2 MiB granularity and a constant page
 * offset. Four observers have already shown the fault is not software: the PTE
 * the driver writes is right, the PTE in memory is right, and the data read
 * directly at the physical address (with no VA at all) is right. Only the
 * GPU gets it wrong.
 *
 * That leaves the GPU's own translation path. And inside it there is a cache
 * nobody had looked at: the L2 caches PAGE TABLE LINES. A page table block
 * (PTB) is memory like any other -- it gets freed and reallocated. If the
 * physical address of an old PTB is reused by a new PTB, the CPU writes the new
 * PTEs there, but the L2 may keep serving the OLD LINES for that address. The
 * walker reads the previous generation's table, and the result has exactly the
 * measured shape: a whole block resolved through other blocks' pages, in the
 * order they had in the old PTB.
 *
 * This also explains the two facts that never fit anything:
 *
 *   - bimodal per process, deterministic and persistent: it depends on that
 *     process's PTBs landing on freshly reused addresses, and nothing ever
 *     evicts those lines -- because on this board invalidation NEVER happens
 *     (and, when forced, it wedges; see gmc_v10_0.c).
 *   - the rate tracking VRAM size (20.4% at 512 MB, 15.7% at 4 GB,
 *     12.0% at 12 GB): less VRAM, more reuse of PTB physical addresses.
 *
 * What each knob does
 * -------------------
 * bc250_l2_force_miss is a bitmask over GCVM_L2_CNTL3. FORCE_MISS forces the
 * cache to always miss, i.e. to re-read the entry from memory on every
 * translation. It depends on no invalidation at all -- which is why it is usable
 * here, where invalidating wedges.
 *
 *   bit 0 (1) = L2_CACHE_4K_FORCE_MISS     4 KiB pages
 *   bit 1 (2) = L2_CACHE_BIGK_FORCE_MISS   large pages -- ours, at 2 MiB
 *   bit 2 (4) = PDE_CACHE_FORCE_MISS       directories
 *   7 = all three (sledgehammer: if this does not move the rate, the hypothesis dies)
 *
 * bc250_l2_pde0_tag_mode selects how the PDE0 cache generates the TAG. It is a
 * 1-bit field that every hub in the driver, from gfx9 to gfx12, writes as 0 --
 * with a comment from AMD itself saying "XXX for emulation, Refer to closed
 * source code". If tag generation truncates addresses in this memory
 * configuration, two table lines at different physical addresses collide in the
 * cache. That matches the two address groups measured, one at the base of VRAM
 * and one at the top. -1 keeps the driver's default.
 *
 * bc250_l2_disable_bigk_opt disables the large-page optimization in the L2
 * (GCVM_L2_CNTL2.DISABLE_BIGK_CACHE_OPTIMIZATION). A fallback, in case
 * FORCE_MISS pays off but costs too much.
 *
 * All of them are 0444: they apply at init only, so they change via command line
 * plus a reboot, and never in the middle of a run.
 */
/* Not static: mmhub_v2_0.c reads the same values via extern, so both hubs always
 * stay in the same configuration. SDMA reaches memory through the MMHUB, and a
 * good part of the corruption measurements went through hipMemcpy. Same pattern
 * as bc250_tlb_trace, defined in amdgpu_vm.c and read in gmc_v10_0.c.
 */
int bc250_l2_force_miss;
module_param(bc250_l2_force_miss, int, 0444);
MODULE_PARM_DESC(bc250_l2_force_miss,
	"BC-250: mascara FORCE_MISS no cache de tabela de pagina do L2 (1=4K 2=BIGK 4=PDE, 7=todos, 0=padrao)");

int bc250_l2_pde0_tag_mode = -1;
module_param(bc250_l2_pde0_tag_mode, int, 0444);
MODULE_PARM_DESC(bc250_l2_pde0_tag_mode,
	"BC-250: L2_PDE0_CACHE_TAG_GENERATION_MODE (-1=padrao do driver, 0 ou 1=forcar)");

int bc250_l2_disable_bigk_opt;
module_param(bc250_l2_disable_bigk_opt, int, 0444);
MODULE_PARM_DESC(bc250_l2_disable_bigk_opt,
	"BC-250: 1=DISABLE_BIGK_CACHE_OPTIMIZATION no L2 (0=padrao)");
